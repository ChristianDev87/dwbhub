# ADR 0005 — OpenAPI-First Contract Workflow

**Status:** Accepted (2026-05-21)

## Context

Frontend and backend evolve together but must stay strictly synchronised. Hand-maintained TypeScript types or Swagger UIs drift quickly; that drift caused real bugs in v1.

## Decision

- **Schema source:** ASP.NET Core controllers + DTOs annotated for Swashbuckle.
- **Committed contract artifact:** `shared/openapi.yaml`, regenerated by `tools/verify-openapi.ps1` and committed alongside any controller change.
- **Frontend client:** auto-generated from `shared/openapi.yaml` by `scripts/gen-openapi-client.ps1` into `web/src/lib/api/generated/`. Also committed.
- **CI drift check:** both regenerators run in CI; if their output differs from the committed files, the build fails.

## Consequences

- API-touching PRs include three coordinated artefacts: controller change, `openapi.yaml` diff, generated client diff.
- Code reviewers can read the OpenAPI diff to understand contract changes at a glance.
- Frontend gets type-safe API clients for free.
